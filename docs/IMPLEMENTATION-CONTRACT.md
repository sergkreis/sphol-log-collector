# Collector v1 implementation contract

Normative wire details supplement PROTOCOL.md; endpoints unchanged. No deployment or successful connection is implied. Origin is fixed `https://sphol.com`; JSON UTF-8; redirects forbidden. Client version `0.2.0`.

## Pairing
- POST `/api/collector/v1/pairings`: exact body `{ "challenge": "<base64url SHA256(verifier), without padding>", "challenge_method": "S256", "client_version": "0.2.0", "device_label": "SPHOL Windows collector" }`. Verifier: random 32-byte base64url without padding (43 ASCII characters).
- HTTP 200 or 201: `{ "device_secret": "<opaque 32..512 ASCII non-whitespace>", "user_code": "<4..32 uppercase letters/digits/hyphen>", "verification_uri": "https://sphol.com/collector/pair", "expires_in": 300, "interval": 5 }`. Expiry 1..300 seconds, interval 1..30 seconds. No secrets in URLs.
- POST `/api/collector/v1/pairings/token`: `{ "device_secret": "...", "verifier": "..." }`.
- HTTP 400: `{ "error": "authorization_pending" }` or `{ "error": "slow_down" }`; slow_down adds 5s to polling interval (cap 60). HTTP 403 denied; 410 expired. Other failures retain no credentials and do not report connected.
- HTTP 200: `{ "access_token": "<opaque 32..512 ASCII non-whitespace>", "token_type": "Bearer", "scope": "combat:write", "installation_id": "<1..128 ASCII letters/digits/underscore/hyphen>", "expires_at": "<UTC ISO8601>", "characters": [{ "id": 123, "name": "Exact Character Name" }] }`. Nonempty unique IDs AND unique names; max 32; positive integer IDs; names 1..128 printable chars. Server derives these from authenticated member identities, never client supplied names. Names are case-sensitive exact matches for listener allowlist. Token maximum lifetime is server policy; expiry must be future. Store entire response encrypted with DPAPI CurrentUser. No refresh endpoint.

## Upload
- POST `/api/collector/v1/events` bearer token, body/events exactly as PROTOCOL.md. Only exact approved listener names leave client. Other characters remain pending visibly; never silently upload them. Queue is cleared with explicit confirmation before changing installation/account; no cross-account queue reuse.
- Limit 100 events, 262144 bytes including JSON envelope, text <=8192 UTF-8 bytes, listener <=128 chars. Event ID lowercase hex SHA256 length 64. UTC timestamp accepts `+00:00` or `Z`; server allows up to 7 days old and 5 minutes future (older queue events are rejected, not silently erased).
- HTTP 200: exact keys `accepted_ids` (unique string IDs) and `rejected` (list of exact `{ "id": "...", "reason": "invalid_event" | "unapproved_character" | "id_conflict" | "timestamp_out_of_range" }`). Combined accepted/rejected IDs MUST partition submitted IDs exactly with no duplicate or unknown IDs. Atomic validation/commit before response; only accepted IDs are deleted. A malformed/partial reply acknowledges NOTHING. Rejected events remain pending and uploads pause visibly until user deletes pending or resolves the issue.
- HTTP 401/403 stops uploading; 429 retries using integer Retry-After clamped 1..300s; 5xx/network retry with exponential jitter capped 300s. Other status/schema failures pause, retain queue. No plaintext token fallback; no ESI tokens/session cookies.

## Server security requirements
Approval is authenticated member-only, explicit consent, CSRF + same-origin checked; short code guessing and API creation/poll/upload rate limited; S256 redemption one-use and constant-time; device and bearer secrets hashed at rest; expiry/revocation/membership enforced on every upload (unknown membership fails closed, positive cache <=60s). Website development bypass must not apply. Bind listener names to the stored installation character IDs; do not accept names as authorization by themselves. Idempotency `(installation_id,event_id)` with canonical payload digest, no overwrite. No raw combat content or credentials in diagnostics. Member-only rendering escapes text. Website revocation required; local unpair is not remote revocation.
